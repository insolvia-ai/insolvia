# insolvia_tokens

The **single source of truth** for every Insolvia design token.

Insolvia ships three front-end stacks — Flutter (desktop + web app), React
Native (the app being migrated to), and React/Tailwind (marketing and other web
surfaces). Hand-maintaining a palette in three places guarantees drift, so none
of them owns the values: `tokens.json` does, and a small script renders it into
all three.

```
tokens.json  ──┬──▶ packages/insolvia_design_system/lib/src/tokens/colors.dart
               ├──▶ packages/insolvia_design_system/lib/src/tokens/spacing.dart
               ├──▶ packages/insolvia_design_system/lib/src/tokens/radii.dart
               ├──▶ packages/insolvia_design_system/lib/src/tokens/semantics.dart
               ├──▶ packages/insolvia_design_system_react/src/styles/theme.css
               └──▶ packages/insolvia_tokens/src/tokens.ts
```

## The rule

**Never hand-edit a generated file.** Every one of them opens with a
`DO NOT EDIT` banner. Edit `tokens.json`, then regenerate. CI enforces this (see
*Drift check* below), so a hand-edit fails the PR rather than silently surviving
until the stacks disagree.

The banners are not identical, deliberately. The four Dart outputs name the
Dart regeneration command; `theme.css` points back at this README; `tokens.ts`
names `npm run tokens`. `theme.css` and the Dart files are the outputs that land
inside version-gated design-system packages, so their bytes are expensive —
keeping a toolchain-specific command out of `theme.css` is what let the
generator be re-implemented in TypeScript while rewriting zero generated bytes
and needing no design-system PR. (The Dart banners still name `dart run …` for
exactly that reason: changing them would cost a design-system PR and buy
nothing.)

## Regenerating

From the repo root:

```bash
npm run tokens
```

The generator is intentionally dependency-free (`node:fs` + `node:path` only —
no Style Dictionary, no build step, no devDependency of its own). At this token
count a single readable script beats a configuration-driven pipeline.

What keeps that true after the port is **Node's native TypeScript
type-stripping** (Node >=24): `npm run tokens` is plain
`node packages/insolvia_tokens/tool/generate-tokens.ts`, with no loader, no
bundler and no compile step. The one cost is that type-stripping cannot execute
`enum`, `namespace`, or constructor parameter properties — `erasableSyntaxOnly`
in `tsconfig.base.json` turns using one into a typecheck error rather than a
runtime crash.

### Two generators, for exactly one PR

`tool/generate_tokens.dart` and `tool/generate-tokens.ts` both exist right now
and **must produce byte-identical output**. That is the whole acceptance test of
the port: running either one leaves the other's committed files untouched. Both
drift checks run in CI (see below) — two required checks proving the same
property, on purpose, because running both against the committed files is the
only thing that can falsify the claim.

The Dart generator, and the four `.dart` outputs, go away with the rest of the
Flutter stack. `generate-tokens.ts` is what survives.

## Drift check

```bash
npm run tokens:check
dart run packages/insolvia_tokens/tool/generate_tokens.dart --check
```

Regenerates in memory and exits non-zero, listing the offending paths, if any
committed output differs. The npm check is wired into
`.github/workflows/design-system-react-pr.yml` and covers all six outputs; the
Dart one is in `.github/workflows/design-system-pr.yml` and covers the five it
knows about.

## Token structure

| Group | Consumed by | Notes |
|---|---|---|
| `palette` | Dart only | Raw brand primitives (`ink`, `brass`, `paper`, …). **Not** emitted as CSS variables or TypeScript exports — see below. |
| `spacing`, `radii` | all three | Dart and React Native get logical/density-independent pixels; CSS gets `rem` (`radii` carries an explicit `css` value). |
| `shadows` | CSS only | Flutter takes elevation from Material; React Native's shadow model is per-platform and not worth a shared token yet. |
| `fonts` | CSS + TypeScript | Flutter's type scale lives in `typography.dart`. |
| `semantic` | all three | The indirection layer, with a `light` and `dark` mapping per token. |
| `semanticDerived` | all three | Hover/active states computed from another semantic token. |

Every token carries a `description`. That string becomes the doc comment on the
generated Dart member and on the generated TypeScript member, so the JSON is the
only place documentation is written.

### Semantic indirection

Raw palette names are an implementation detail. Consumers — components, themes,
and downstream apps — speak only the semantic vocabulary (`primary`, `accent`,
`bg`, `ink`, `muted`, `line`, `card`, `danger`, …), and a re-brand swaps the
mapping in one file instead of touching every call site. This is why neither the
CSS nor the TypeScript output emits palette names at all: there is nothing for a
consumer to accidentally couple to.

`semanticDerived` tokens keep that property for interaction states. In CSS they
emit `color-mix(in srgb, var(--color-primary) 88%, black 12%)`, so overriding
`--color-primary` also moves its hover state. Dart and React Native cannot defer
that computation, so the generator pre-computes the identical sRGB blend at
generation time — all three stacks land on the same pixel.

On the Dart side the layer is `InsolviaSemanticColors.light` / `.dark`, which
`InsolviaTheme` reads instead of reaching for `InsolviaPalette` directly.

## The TypeScript output

`src/tokens.ts` is the React Native app's copy, imported as `@insolvia-ai/tokens`
and fed straight to `StyleSheet.create`. Plain exported consts: `colors`
(`light` + `dark`), `spacing`, `radii`, `typography`. No CSS, no Tailwind, no
runtime, no dependencies.

Its types are the point. `ColorScheme` declares every semantic role as required,
and `colors` is checked against `Record<ColorSchemeName, ColorScheme>`, so **a
missing dark-mode value is a compile error** rather than an `undefined` that
renders as a transparent box on one theme. A `ColorSchemeName` that is named but
never declared trips a `never` assertion in the same file. This is the
"you cannot compile until you declare it" property the app already relies on in
`apps/insolvia_app/lib/config/environment.dart`, where the environment switches
have no default arm.

The package is private and unpublished; `src/tokens.ts` is exported as source
and consumed by symlink, so there is no build output and no version gate.
